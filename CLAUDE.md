## Project Overview

A Discord-like WebRTC video chat and messaging platform. Three services run behind an Nginx reverse proxy:
- **`goserver/`** — Go REST API + WebRTC signaling server (WebSocket)
- **`chatserver/`** — Node.js text chat server (WebSocket)
- **`vueclient/`** — Vue 3 SPA frontend

## Commands

### Go Backend (`goserver/`)

```sh
cd goserver
go build -o bin/api ./cmd/api   # build
make test                        # run tests (uses gotestsum)
make lint                        # lint (golangci-lint)
make fmt                         # format (gofmt + goimports)
make api                         # regenerate server code from openapi.yaml
go run ./cmd/api                 # run directly
```

Single test: `cd goserver && go test -run TestName ./internal/pkg/jwt/...`

### Vue Frontend (`vueclient/`)

```sh
cd vueclient
npm install
npm run dev          # dev server (Vite)
npm run build        # type-check + build
npm run lint         # ESLint --fix
npm run format       # Prettier
npm run type-check   # vue-tsc
```

### Chat Server (`chatserver/`)

```sh
cd chatserver
npm install
npm run dev   # node --watch src/server.js
```

### Docker (full stack)

```sh
# Localhost dev
./generate-ssl-localhost.sh
docker-compose -f docker-compose.localhost.yml up --build

# Production
docker-compose -f docker-compose.prod.yml up --build
```

## Architecture

### Go Server — Clean Architecture

```
goserver/
  cmd/api/main.go          # Entry point; uses squad + healing for graceful shutdown
  internal/app/api.go      # Wires up all dependencies
  internal/config/cfg.go   # Env config (prefix: MYDISCORD_)
  internal/domain/         # Domain types and errors
  internal/ports/          # Service and repository interfaces
  internal/services/       # Business logic (auth, user, room)
  internal/adapter/
    handler/               # HTTP handlers (generated StrictServer interface)
    repository/sqlite/     # SQLite repos via modernc/sqlite
    repository/accesstoken/# In-memory access token cache (TTL)
  internal/gen/api/        # AUTO-GENERATED from api/openapi.yaml — do not edit
  migrations/              # Goose SQL migrations
  api/openapi.yaml         # Source of truth for API; run `make api` to regenerate
```

**Config env vars** (prefix `MYDISCORD_`):
- `MYDISCORD_PORT` (default 8080), health check on 8081
- `MYDISCORD_DATABASE_DSN`, `MYDISCORD_DATABASE_SALT`
- `MYDISCORD_AUTH_TOKEN_SECRET` — must match the chat server's `MYDISCORD_AUTH_TOKEN_SECRET`

**API code generation**: `make api` runs `oapi-codegen` against `api/openapi.yaml` and writes to `internal/gen/api/`. Never edit generated files manually.

### Vue Frontend — Feature-Sliced Design

```
vueclient/src/
  app/           # Router, App.vue
  pages/         # Route-level pages (auth, home)
  widgets/       # Composite UI blocks (Sidebar, ChannelView, ChatPanel, etc.)
  features/      # User-facing feature forms (auth)
  entities/      # Business entity components (VideoTile, ParticipantCard)
  shared/
    stores/      # Pinia stores (see below)
    lib/         # Composables: useWebRTC.ts, useApiErrors.ts, useNotifications.ts
    i18n/        # vue-i18n; locales: en.ts and ru.ts
    ui/          # Generic UI components
  api/           # OpenAPI-generated client (committed, not auto-generated by build)
```

**Pinia stores** (`shared/stores/`):
| Store | Responsibility |
|---|---|
| `authStore` | JWT access/refresh tokens, localStorage |
| `signalingStore` | WebSocket to `/api/v1/ws`; WebRTC signaling messages |
| `chatStore` | WebSocket to `/api/v1/chat/ws`; text messages, reactions |
| `roomStore` | Room list + participants (REST API) |
| `callStore` | Whether user is in an active call |
| `settingsStore` | User preferences (camera/mic device IDs) |
| `sidebarStore` | Sidebar open/closed state |
| `voiceStateStore` | Local voice activity state |

### WebRTC Signal Flow

1. `useWebRTC.ts` composable manages all peer connections.
2. `signalingStore` manages the WebSocket connection and message dispatch.
3. On `peer-joined`, the existing client creates an SDP offer → sends via signaling WS.
4. State (mic/video/screen) is broadcast to peers via `RTCDataChannel` (`state-channel`).
5. Sound events (`connect`, `disconnect`, `screen-share-start`, etc.) go via both the signaling WS (`sendEvent`) and data channels.
6. Screen share sends **video** + optional **screen audio** (separate track with `contentHint = 'screen'`) distinct from the microphone track.

### Chat WebSocket Protocol

Chat server connects at `wss://.../api/v1/chat/ws?token=JWT&room=ROOM_ID`. Supports: `chat_message`, `typing`, `edit_message`, `delete_message`, `add_reaction`, `remove_reaction`. Server broadcasts `chat_history` on join, keeps last 50 messages per room in memory.

### Nginx Routing

- `/api/v1/ws` → Go server WebSocket (signaling)
- `/api/v1/chat/ws` → Chat server WebSocket
- `/api/v1/*` → Go server REST
- `/*` → Vue static files
