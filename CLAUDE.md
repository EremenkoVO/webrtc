## Project Overview

A full-stack WebRTC video conferencing platform with real-time chat, consisting of four components: Go REST/WebSocket backend, Vue.js web client, Electron desktop client, and a Node.js chat server, all proxied through Nginx.

## Components & Commands

### Go Backend (`goserver/`)
```bash
make build    # Build binary to bin/api
make api      # Regenerate code from OpenAPI spec (api/openapi.yaml) using oapi-codegen
make test     # Run tests
make lint     # Run linter
make fmt      # Format code
go run ./cmd/api/main.go  # Run directly
```

Environment variables (prefix `MYDISCORD_`): `PORT`, `DATABASE_DSN` (SQLite path), `DATABASE_SALT`, `AUTH_TOKEN_SECRET`.

### Vue Web Client (`vueclient/`)
```bash
npm run dev          # Dev server on port 5173
npm run build        # Production build
npm run type-check   # TypeScript checking
npm run lint         # ESLint + fix
npm run format       # Prettier
```

### Electron Desktop Client (`electron-client/`)
```bash
npm run dev           # Dev mode (renderer only)
npm run electron:dev  # Full Electron dev with hot reload
npm run build         # Build for current platform
npm run build:mac     # macOS DMG + ZIP
```

### Chat Server (`chatserver/`)

## Architecture

### Request Routing (via Nginx)
- `/api/v1/ws` → Go backend WebSocket (port 8080) — WebRTC signaling
- `/api/v1/**` → Go backend REST (port 8080)
- `/api/v1/chat/ws` → Chat server WebSocket (port 3001)
- `/**` → Vue frontend static files

### Go Backend Structure (Hexagonal Architecture)
```
goserver/
├── cmd/api/main.go              # Entry point
├── internal/
│   ├── domain/                  # Domain models
│   ├── services/{auth,user,room}/ # Business logic
│   ├── adapter/
│   │   ├── handler/             # HTTP handlers (auth.go, rooms.go, middleware.go)
│   │   └── repository/sqlite/   # SQLite data access
│   └── ports/http.go            # HTTP server setup
├── api/
│   ├── openapi.yaml             # Source of truth for API spec
│   └── cfg.yaml                 # oapi-codegen config
└── migrations/                  # SQL migrations (auto-applied on startup)
```

**API code is generated** — edit `api/openapi.yaml` then run `make api`. Don't manually edit generated files.

### Vue/Electron Frontend Structure (Feature-Sliced Design)
```
src/
├── api/          # Generated API client
├── app/          # App.vue + router.ts
├── entities/     # Data models
├── features/     # Feature modules
├── pages/        # Route-level page components
├── shared/       # Utilities, shared components
└── widgets/      # Reusable composite UI components
```

The Electron client (`electron-client/src/`) mirrors the Vue web client structure. Electron-specific code lives in `electron/main.ts` (main process) and `electron/preload.ts` (IPC bridge).

### WebRTC Signaling Protocol
The Go backend acts as a WebSocket relay for WebRTC negotiation. Clients exchange SDP offers/answers and ICE candidates through the server. See `vueclient/SIGNALING_GUIDE.md` for the full message protocol.

### Chat Server
Stateless in-memory store (Maps for rooms/clients). Verifies JWTs using the same secret as the Go backend. Fetches usernames from `GET /api/v1/me`. Retains last 100 messages per room.

## Key Conventions

- **Authentication**: JWT access + refresh tokens. Shared `AUTH_TOKEN_SECRET` across Go backend and chat server.
- **API Evolution**: Always update `goserver/api/openapi.yaml` first, then regenerate with `make api`.
- **SQLite**: Single file database. Migrations in `goserver/migrations/` run automatically on startup.
- **CORS / SSL**: Nginx handles SSL termination; self-signed certs for localhost dev (generated by `generate-ssl-localhost.sh`).
- **Electron IPC**: All native OS access goes through `electron/preload.ts` bridge — never access Node APIs directly from the renderer.
